# Docs 11, 12, 13, 14, 17 implemented: departments, model split, Excel round-trip, dashboard, optional tags

One migration (`0005_department_model_split.sql`), all five phases. **Deployed**
to the droplet 2026-08-01 via CI (commit `8dbf832`): the migration applied to
the production database on API boot — all six new asset columns present, the
`department` table created with Repair & Maintenance seeded for the existing
tenant, and `drizzle.__drizzle_migrations` at 6 entries. Site serving
`/health` 200.

## What shipped

**Docs 11 + 17 together (one migration, as ordered):** `department` table;
`asset.costTarget`/`asset.owningDepartmentId`; `asset.tag` nullable; the "Needs
a Tag" report; the add-tag action on the tool detail page; and the Tag
component rendering `no tag` instead of an empty pill on web and mobile.
`asset.create`/`import`/`applyIntake` and the `action.submit` intake gate all
accept an untagged tool — the gate is now "a make or a description".

**Doc 12:** `asset.model_name` → `make`/`modelNumber`/`description` (+`otherRef`
from doc 13). One shared `formatAssetModel` in `@stinventory/types`, used at
every display site, so a register row, a chat card, a report and an overdue
email cannot disagree. All `ilike` searches span the three columns. Seed
rewritten to set the split fields directly.

**Doc 13:** `.xlsx`/`.xls` import via SheetJS (web-only dep), header-row
detection for the trailer sheets' title blocks, a spec-driven round-trip export
on the Tool Register and per-location export on the Locations page, `OTHER`
aliased to `good` on import, and a preview warning for rows with neither tag nor
serial. The header-normalisation the spec describes was **already in the code**
(`csv.ts`'s `normalizeHeader` + alias table, landed 2026-08-01) — no change was
needed there.

**Doc 14:** `dashboard.kpis.missingSerial`; capital-on-jobs and capital-in-shop
tiles fed by `capitalByProject`/`capitalByDepartment`; the "Loans to verify"
attention card (the `attention` empty-state keeps summing the full list);
`byMechanic`, `capitalByDepartment` and `needsTag` reports in the registry; and
the "Scheduled maintenance" placeholder tile labelled as not-built-yet.

## Found while building

- **Doc 13's "per-trailer export" names a screen that does not exist.** There is
  no `locations/[id]/page.tsx` — the code has a single list page. I put the
  export button on the rows of that list (fixed and vehicles both), emitting the
  import spec's columns with a one-cell title block above the header, which the
  new header detection already skips on re-import.
- **Doc 17's "relax the unique list" is a no-op in the code.** The dedupe logic
  skips empty values, so a blank tag never collides; keeping `tag` in
  `unique` still dedupes tagged rows on re-import. "Relaxing" would only lose
  that. Left as-is.
- **Doc 17's mobile "per-row menu for untagged tools" does not match the app.**
  The mobile list screens have no per-row menus — every row navigates to the
  tool detail, whose action chips work by `assetId` with no tag involved. An
  untagged tool is fully actionable on mobile already; only the Tag rendering
  needed changing.
- **The intent `draft` for `request_purchase` is folded into `description`** —
  `modelName` no longer exists, and the prose ("another rotary hammer") is
  exactly what the description column is for.
- **`drizzle-kit generate` prompts interactively on the `model_name`→`make` drop**
  (it suspects a rename). It reads raw keypresses from the tty, so piped input
  is ignored; the migration was generated by driving the prompt with a pty and
  sending carriage returns.

## What was deliberately not done

- The spec-driven register export emits `owning_project`/`location` names (refs
  resolve by name) but **not a department column** — the import spec has none,
  so it would not round-trip. Department-charged tools export with a blank
  `owning_project`, which imports fine as "no project".
- The `asset_model`/`manufacturer`/`modelId` tables stay untouched and vestigial.
  Nothing reads them; wiring the split columns through them is its own change.
- No maintenance tables: the dashboard tile is an honest `0` placeholder.
- `docs/15-vendors-and-orders.md` not implemented — roadmap, not a spec.
