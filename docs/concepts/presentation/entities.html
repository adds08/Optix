Entity identifiers

The code, the label, and the prefix

How Optix names the four things it tracks — projects, small tools, equipment and people — and which of them the system makes up for you.

Bodhi Labs · Optix Entity IdentifiersTitle
One line to open: every entity Optix tracks has a code you can read out, and a name a person would use. Where it has sub-kinds, the code carries a prefix; where it does not, it deliberately has none.

The rule

One rule, three parts

The code

The stable handle. What the system stores, what the ledger references, and what somebody reads out on the radio. A code is never a name.

The name / description

The human label. What the tool is, what the job is called, who the person is. This can change; the code does not.

The prefix

The family. Present when the entity has sub-kinds to tell apart; deliberately absent when it does not.

Renaming a tool, moving it to another job or changing its holder never changes its code. The code is the one thing that follows the entity for life.

The project code doubles as the external id (FoundationSoft's key). It is optional, so a job can exist with only a name — and that is exactly why imports match projects by name and why two identically named jobs would be a problem.

Entity 2 of 4

Small tools

  • Prefix TOOL — one fixed prefix for the whole register; tools have no sub-kinds to tell apart.
  • Code TOOL-00001 — generated when blank, padded to five digits, and it widens rather than wraps past 99,999 (TOOL-100000).
  • Label: description — required in the import; in the app, a make or a description is required, model number always optional.
  • A second identifier: serial — the manufacturer's number, unique when given. It is what a police report needs, so it must never collide.

Optix mints this one

Urban's sheets carry no tool-ID column at all — all 753 rows arrive blank — so the system generates every code.

Codes are compared case-insensitively (tool-00001 and TOOL-00001 are the same tool), but a typed code is stored exactly as typed: TOOL-7 and TOOL-00007 stay different codes.
Bodhi Labs · Optix Entity IdentifiersSmall tools
Only 317 of the 753 rows in the real import carry a serial, and the source had 13 duplicated serial values the importer refuses. That is precisely why a generated code exists: there must be one identifier every single tool has, because the serial is not it.

The guard rails

Uniqueness at the door

A duplicate is refused, never merged. Each entity checks a different pair, and a blank is skipped rather than treated as a value.

TOOL-00042
Padded to five, stored as the code
  • Inside the transaction. Reading max + 1 outside one lets two concurrent creates take the same number.
  • Not a database sequence. A sequence is per-database where codes are per-tenant, cannot be reset, and leaves gaps that read like missing tools.
  • Hand-typed codes never push the counter. A typed TOOL-99999 does not send every future generated code to six digits.
  • Manual codes are kept verbatim. If somebody types their own code, Optix stores exactly what they typed and flags it as manual.
Bodhi Labs · Optix Entity IdentifiersCode generation
This is the only generator in the system, and it is deliberately small and testable: the pure half (what is the highest number, what does the next code look like) is unit-tested without a database.

Worth remembering

Five things to watch

1

Codes are typed, not normalised

SUV-2 is real. Padding is what the generator produces; it is not a rule applied to what a person types.

2

Project code is optional

Without it the name is the only label — and name-matching is how imports resolve projects. Two jobs with one name is a real risk.

3

Equipment prefixes are manual

TRK, TE and SUV are conventions in the data, not rules enforced by Optix. A mis-prefixed code is still accepted.

4

The serial cannot be the only key

Only 317 of 753 carry one, and the source had 13 duplicated values the importer refuses. That is why the generated code exists at all.

5

Two people numbers, on purpose

Urban's badge number is the code; BambooHR's id is an external reference. The read-only sync can never rewrite the badge.

The short version

One code per entity, guaranteed present. A name to read. A prefix only where the kind matters.

Bodhi Labs · Optix Entity IdentifiersCaveats
Close on the short version. Every caveat here is a real state of Urban's data, not a limitation of the model — the model is honest about what the source files contain.
