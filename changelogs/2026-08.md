### Restructure the shell around modules, and make Settings a rail destination

**Files:** `apps/web/components/sti/nav-config.ts`, `components/app-rail.tsx`,
`components/app-sidebar.tsx`, `components/sti/app-shell.tsx`,
`app/(app)/settings/` (split into three routes), `components/settings/tenant-settings.tsx`
**Why:** The rail's groups were a flat list of screens, not modules, and the shell is the
frame the rest of the product gets built into. "Equipment" named the group holding Custody
and the map — things you *do* — while the register, the thing you *keep*, sat three groups
away under "Entity", so a new module had no obvious place to land. Operations now holds the
functions and Equipment holds the equipment; People and Projects became Organization.
Configuration stopped being a module: Settings is pinned to the rail's foot under the
assistant, and users, roles, theming and the API keys are rows inside it. Inbox left the
desk nav entirely — it is a queue, not a record, and the bell already carries its count.

`NavGroup` gained an explicit `icon` (the rail borrowed `items[0].icon`, so reordering rows
silently moved the target somebody had learned to aim at) and a `placement` field, so
pinning a group to the foot is a config entry rather than a branch in the rail.

Splitting Settings into routes exposed a latent bug in every consumer: they matched a
pathname with `startsWith` against the list in declaration order and took the first hit,
which is correct only while no nav href is a prefix of another. On `/settings/ai`,
`/settings` matched first — wrong row lit, wrong group resolved. `matchItem` now returns
the longest match and all three callers use it.

The split deliberately did not gate the Settings group as a whole. Appearance saves through
`preferences.set`, which writes the caller's own row and needs no permission; gating the
group would have put a foreman's font size behind `config.manage` — a regression the old
combined page defended against with a `personal` escape hatch. Per-row `perm` plus the
shell's existing drop-empty-groups rule reproduces that outcome structurally, and the
escape hatch is gone.
**Verified:** `pnpm typecheck` (13 tasks) and `pnpm test` pass; `pnpm --filter
@stinventory/web lint` is error-free (12 pre-existing warnings, none in new files).
`/settings`, `/settings/ai`, `/settings/appearance` and `/tools` all serve 200 against the
running dev container with nothing in `docker logs stinventory-web`. **The rendered rail
has not been looked at in a browser** — compilation is not layout.
**Left undone:** `/inbox` stays in the FIELD nav as "Alerts". A foreman's whole job on that
layout is the alerts list, and a bell icon on a phone is a worse place to bury it than a nav
row; say so if it should go from there too. The table and page-header work discussed
earlier is still unstarted and unapproved.

### Repair the duplicate-`0022` migration collision that failed CI

**Files:** `packages/db/drizzle/0024_recover_orphaned_0022.sql`,
`packages/db/drizzle/meta/`, `docs/tickets/STATUS.md`
**Why:** CI's schema-drift step failed on every run. Two branches had each generated an
idx-22 migration; the merge in `9f84d93` resolved `meta/_journal.json` by taking the
side with no idx-22 entry at all, and kept the older of the two `0022_snapshot.json`
files. Three consequences, all live: `drizzle-kit generate` diffed the schema against a
snapshot predating `vehicle_one_truck_per_foreman_uq` and so re-emitted it forever;
`db:migrate` skipped both orphaned `.sql` files because the journal never referenced
them, so a fresh database got neither the index nor the `blocky` theme default; and
databases migrated before the merge diverged from ones migrated after. Both statements
were folded into one forward migration rather than back-dating a journal entry, because
drizzle's migrator applies strictly by timestamp and would have skipped a back-dated
entry on any database already past `0023`.
**Verified:** `pnpm db:generate < /dev/null` prints `No schema changes, nothing to
migrate` — the sentinel CI greps for — with a clean tree. Migrated a throwaway
`sti_migrate_check` database from zero in the api container: `pg_indexes` carries
`vehicle_one_truck_per_foreman_uq` and `user_preferences.theme_name` defaults to
`'blocky'::text`. Database dropped afterwards; the local dev database was not touched.
**Left undone:** No CI guard yet for the class of failure — a `drizzle/*.sql` with no
journal entry. That is what would have caught the merge on the day it happened.
**Commit:** `b6d4517`, where a concurrent session swept it in under the subject
`# globally fixed layout`. `meta/0022_snapshot.json` was deleted in that same commit;
harmless, since `generate` diffs against the newest snapshot and `migrate` reads only
the journal, and the folder already tolerates snapshot gaps at 0009, 0020 and 0023.
